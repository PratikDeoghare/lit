Tutorial: a legacy script, start to finish

Read this top to bottom, no demos needed. It follows one small script, invoice.py, through every tool. Each command's output is what the installed lit printed when I ran it on this exact project, with the home directory shortened to ~.

  1. Install

    Put the binary on your path, then put the skill where Claude looks for skills.

    [[term:t1:lit install-skill]]

  2. Start from code nobody wants to read

    This is the whole program: three functions and a demo. It works. It does not say why Oregon is special, where the tax rate comes from, or what happens at 100 units.

    [[code:invoice.orig.py:invoice.py]]

    Keep a copy of the original. You will compare against it in a moment.

    [[cmd:cp invoice.py ../invoice.orig.py]]

  3. Ask Claude

    Open Claude in the project and give it the prompt from above. It reads the code, runs it, and writes invoice.lit. Here is the part of the document that covers pricing. The prose is new, and the code is the original, line for line.

    [[file:invoice.before-absorb.lit:12:35:invoice.lit]]

    The same document ends with an Open questions section for things the code does not settle. That section is how you tell an explanation from a guess.

  4. Check it

    Lint checks the document's structure. Tangle writes the code into the project, next to where it always lived, so nothing about the build changes. Then compare against your copy.

    [[term:t1:lit lint invoice.lit]] [[term:t1:lit tangle invoice.lit .]] [[term:t1:diff ../invoice.orig.py invoice.py]]

    No output from diff means the generated file is identical to the original. The behaviour cannot have changed, and the program still runs:

    [[term:t1:python3 invoice.py]]

  5. Read it

    Weave turns the document into a page with a table of contents, numbered chunks you can click through, and a chunk index. It also writes LaTeX, ready for your own engine.

    [[term:t1:lit weave invoice.lit -o site]]

    Open site/invoice.html in a browser. A .lit file is also perfectly readable in any editor, because it is plain text.

  6. Find your way around

    Tangle also wrote a sourcemap. Ask where line 23 of invoice.py came from, and then where line 66 of the document ends up. Output is path:line:column, which most editors can jump to.

    [[term:t1:lit addr invoice.lit invoice.py:23]] [[term:t2:lit addr invoice.lit invoice.lit:66]]

  7. A teammate changes the code

    Someone fixes invoice.py in their editor without knowing a document exists. They raise the discount threshold to 12 and add a guard for an empty order.

    [[term:t2:diff ../invoice.orig.py invoice.py]]

    Ask absorb what it would do. It maps each changed line through the sourcemap to the chunk that wrote it, and removes the indentation that references added.

    [[term:t2:lit absorb invoice.lit --dry-run]]

    Looks right. Run it for real, without --dry-run. Then see what it did to the document.

    [[term:t2:lit absorb invoice.lit]]

    The code in the document now matches the code in the project. The prose does not: it still says the discount starts at 10 units. Absorb changes code and never prose, because only you know what the words should say.

    [[term:t2:grep -n From 10 units invoice.lit|grep -n "From 10 units" invoice.lit]]

    Fix the sentence in the document. That is an ordinary edit.

  8. You both edit, on the same day

    You raise the tax rate in the document. Meanwhile the teammate exempts New Hampshire in invoice.py. Whichever of tangle and absorb you ran first used to decide whose edit survived. Sync remembers what both sides looked like at the last agreement, and compares each against that.

    [[term:t3:lit sync invoice.lit status]] [[term:t3:lit sync invoice.lit diff]]

    Two changes in different places. Merge brings each across, in its own direction.

    [[term:t3:lit sync invoice.lit merge]] [[term:t3:lit sync invoice.lit status]]

  9. When you touch the same line

    You set TAX = 0.0925 in the document. The teammate sets TAX = 0.09 in the file. Merge will not choose for you.

    [[term:t4:lit sync invoice.lit merge]]

    Nothing was changed. You can decide with --prefer lit, --prefer gen or --prefer newer, or pick by hand, as in the step after next. Here the document wins. The losing text is not gone:

    [[term:t4:lit sync invoice.lit merge --prefer lit]] [[term:t5:lit sync invoice.lit restore invoice.py --list]]

  10. You forgot to sync and ran tangle

    Tangle rewrites generated files. If one holds an edit that the document does not have, tangle says so and keeps a copy first.

    [[term:t5:lit tangle invoice.lit .]] [[term:t5:lit sync invoice.lit restore invoice.py --list]]

    Bring one back with lit sync invoice.lit restore invoice.py --sha ba30967a, or print it with --stdout.

  11. Choose, change by change

    Pick walks through every region, like git add -p but in both directions. Here the document changed one line, the file another. The keys are in the prompt: apply, leave alone, revert, edit, and so on. I answered y, n, then y to write.

    [[pick]]

    The change from the document went into the file. The file's change was left pending, so it is still there next time:

    [[term:t7:lit sync invoice.lit status]]

  12. Watch, if you like

    Watch records every change to the document and its files, and never modifies anything. Leave lit watch invoice.lit running in a terminal. With --once it records what changed since it last ran and exits.

    [[term:t6:lit watch invoice.lit --once]]

    lit sync invoice.lit log then shows the journal, and sync ... merge --prefer newer uses the recorded edit times to settle conflicts.

  13. Remove it

    When you are done, one command removes the skill and, after asking, the package.

    [[term:t7:lit uninstall-skill]]

    Plain lit uninstall removes the skill and then asks before it removes the package. Add --yes to skip the question.
